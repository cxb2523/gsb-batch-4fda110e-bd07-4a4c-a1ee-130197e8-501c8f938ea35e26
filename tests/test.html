ExposureMonitor 本地测试页

本页用于验证 exposure-monitor.js（本地持仓 CSV 轮询与状态层）的全部状态分支。 页面顶部固定的状态栏与其下方的净敞口区即被测组件， 与 index.html 中注入的是同一份实现。

1. 如何指定被轮询的文件

  • URL 查询参数：在地址栏使用 ?csv=positions-bad-row.csv（路径相对本页）， 可加 &interval=1000 调整轮询间隔（毫秒，默认 3000）。
  • 页面控件：在下方输入框中填写路径，点击「切换文件」；或直接点击各样例快捷按钮。
  • 不指定时，本测试页默认轮询 positions-valid.csv； index.html 默认轮询其同目录下的 positions.csv。

2. 如何触发一次轮询

  • 自动：页面按固定间隔（默认 3 秒）轮询一次，可用下方「自动轮询」开关暂停/恢复。
  • 手动：点击「立即轮询」按钮，立即读取并解析当前文件一次。

3. 如何观察结果

  • 状态栏颜色与文案：页面最顶部的彩色横条，颜色随状态切换（见第 5 节对照表）。
  • 净敞口区：状态栏下方一行，正常时按币种显示净敞口（正=绿色、负=红色）； 任何异常状态下都会清空为「— 无可用敞口数据 —」，不会沿用上一次的敞口。
  • 最后更新：状态栏右侧时间戳，仅在全部持仓行合法时刷新。

4. 轮询控制

样例快捷切换：
file:// 回退（无法 fetch 本地文件时）： 选择后以其内容为数据源；文件改动后需重新选择。

5. 状态判定条件对照表

状态状态栏颜色判定条件敞口区 / 最后更新
数据正常 绿色 文件可读取；首个非空行恰为表头 品种,方向,手数,合约规模,保证金； 且至少有一行持仓，全部持仓行均合法（5 个非空字段、品种为 6 位字母、 方向可识别、手数/合约规模为正数、保证金为非负数值）。 更新敞口（多：基准币正/计价币负；空：相反；手数×合约规模按币种求和）并刷新最后更新时间。

无持仓（表头合法，无持仓行） 蓝色 表头合法，但之后没有任何持仓行。 敞口区清空；时间不刷新。

6. 本地运行方式（不依赖网络）

# 推荐：在本 tests 目录起一个本地静态服务（localhost，不访问外网）
cd tests
python -m http.server 8000
# 浏览器打开 http://localhost:8000/test.html

直接双击以 file:// 打开时，多数浏览器禁止 fetch 读取本地文件， 状态栏会显示红色「持仓文件缺失或不可读取」——这本身也是对该状态的一次验证。 此时可改用上方「file:// 回退」的文件选择器指定数据源， 或使用允许本地文件读取的浏览器启动参数（如 Chrome 的 --allow-file-access-from-files）。

7. 异常后自动恢复验证

先切到任一样例异常文件（如「坏行」），确认状态栏变为对应颜色且敞口区清空； 再点「合法」按钮（或把被轮询的文件改回合法内容），无需刷新页面， 下一次轮询（或点「立即轮询」）即自动回到绿色「数据正常」态并重新显示敞口。
