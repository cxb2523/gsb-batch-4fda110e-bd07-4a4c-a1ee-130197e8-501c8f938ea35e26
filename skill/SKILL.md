# SourceBoard：搜平台、抓链接、出看板

本机装了 `sourceboard` 命令。它只读公开数据，不登录任何账号。大部分数据走 TikHub，按次收费，钥匙已经存在本机，你不需要也不应该读它。

没装或没配好时（`sourceboard doctor` 报 tikhub 不是 success），按仓库的 `AGENT_INSTALL.md` 带用户配置，不要自己找别的办法绕。

## 什么时候用哪个命令

| 用户要什么 | 命令 |
|---|---|
| 按题目找内容、找对标、看有谁做过 | `sourceboard search "关键词" -p 平台 --json` |
| 给了一个作品链接或整段分享文案 | `sourceboard grab '链接或分享文案' --json` |
| 给了一个账号主页链接 | 同上，`grab` 会认出是主页 |
| 一批链接 | `sourceboard grab --input-file 清单.txt --out 目录 --json` |
| 查官方资料、新闻、文档 | 不用它，用你自己的网页搜索 |

平台名：`抖音 小红书 B站 微博 知乎 公众号 youtube reddit tiktok x`，逗号分隔。不写 `-p` 就用用户安装时选的常用平台。

## 每次都要守的规矩

1. **先看价再花钱。** 一次要搜很多平台或抓很多链接时，先加 `--plan` 看预估花费，告诉用户。单次几分钱以内的日常搜索可以直接跑，但回复里要报花了多少。
2. **失败要明说。** 输出里每个平台都有状态：`success` 搜到了、`true_zero` 正常但没结果、`auth_failed` 钥匙或余额有问题、`rate_limited` 被限流、`connector_failed` 接口出错、`not_attempted` 没去取。接口出错不等于网上没有。哪个平台没搜到、为什么，必须告诉用户，不能只报成功的。
3. **数字缺了就是缺了。** 没拿到的数据不要当成 0，也不要猜。搜索结果里抖音的播放量不可靠，要播放量请对具体作品用 `grab`。
4. **中文平台不要合并近义词。** 把几个词塞进一个搜索词会少搜到很多东西。宁可分几次搜，少翻页。
5. **被限流就停。** 看到 429 或限流，不要连续重试，告诉用户稍后再试。
6. **默认不下载图片和视频。** 用户明确要原片时才加 `--with-media`。
7. **这是别人的公开内容。** 用来研究、找选题、做对标。不要帮用户原样搬运。

## 搜完怎么呈现：看板

搜索和抓取都会自动生成 `board.html`。标准做法分三步：

1. 跑命令，拿到输出里的 `results`（或抓取目录）和 `board` 路径。
2. 读 `results.json`（抓取则读各条的 `meta.json` 或 `content.md`），写一份结论，存成结果目录里的 `conclusion.md`。结论要写：
   - 一两句话的总判断；
   - 最值得看的几条，各带卡片编号（如 `[dy03]`）和理由，引用真实数字；
   - 这次哪些平台没搜到、对结论有什么影响；
   - 你拿不准的地方。
   只根据真的搜到的内容写，不补充没搜到的东西。
3. 把结论放进看板并打开：

   ```sh
   sourceboard board <结果目录> --conclusion <结果目录>/conclusion.md --open
   ```

然后在对话里只回三样：看板路径、一句话结论、需要用户做什么（例如“想让我深挖哪几条，在页面上点‘留’，再点底部‘生成回复’贴回来”）。不要把几十条结果全贴进对话。

用户把看板生成的回复贴回来时，里面每条都有编号、平台、标题、链接和备注。照着“留”的那几条继续干，比如逐条 `grab` 拿正文和评论，再出一张新看板。

用户只是问一个小问题、一两句能答清时，不用硬出看板，直接回答并附上链接。

## 常用参数

- `search`：`--sort hot|new`、`--page 2`（每页再收一次钱）、`--no-paid`、`--plan`
- `grab`：`--no-comments`、`--comment-pages N`、`--xhs-reads`（小红书阅读和曝光，每条多约 $0.02）、`--profile-pages N`、`--with-media`、`--no-paid`、`--resume`、`--plan`
- `--json` 的标准输出只有一行摘要；提示和预估在标准错误里。退出码 0 只代表有可用正文，各项能力要看 `capabilities`。
- 钱：`sourceboard account` 看余额，`sourceboard usage --by day --since 7d` 看花费。
- 其他 TikHub 只读接口：`sourceboard api get --path /api/v1/... --param k=v`，同样有缓存和记账。

## 出问题时

- 输出末尾出现“渠道异常”提醒，或 `pending_incidents.count` 大于 0：在回复开头告诉用户哪里坏了、影响什么、建议怎么办，然后运行 `sourceboard incidents notify <编号>`。
- 余额不足：告诉用户去 TikHub 充值，不要换别的办法硬抓。
- 某个平台连续失败：告诉用户这个平台暂时用不了，结论里注明缺了它。
